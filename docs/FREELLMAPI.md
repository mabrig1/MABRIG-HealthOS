# FreeLLMAPI private HealthOS pilot
Upstream: https://github.com/tashfeenahmed/freellmapi/tree/a54da2121a2e14d1ea52941018bdbb44a5364b8f (MIT). Upstream describes a single-user personal experimentation router, not production inference. No public proxy or patient records. No provider quota evasion, account multiplication, or assurance of free capacity. Provider terms and billing controls apply.
## Local router
Clone just this submodule: git submodule update --init vendor/FreeLLMAPI. Follow the pinned docs/en/install/01-install.md for Docker or desktop setup. Keep port 3001 bound to 127.0.0.1. Add your authorized provider keys in the router dashboard, verify each account's free-only billing configuration and terms, and create a named fallback profile healthos-free containing only reviewed free models. Remove paid/custom routes from this dedicated instance. Router-internal retries can use more than one upstream call; HealthOS cannot verify billing or prevent upstream misconfiguration. Do not enable if uncertain.
## Private connectivity
Cloudflare cannot reach your laptop's localhost directly. On an always-on machine or VPS, configure a Cloudflare Tunnel to the local router with hostname llm-private.mabrigkorie.org, protected by a Cloudflare Access service-auth policy (service token only; no bypass/public policy). Restrict access to POST /v1/chat/completions at the tunnel/reverse proxy; keep the admin dashboard and all other routes local. Do not expose port 3001 publicly. The hostname is a proposed configuration, not created by this change.
## HealthOS configuration
Deploy current main. In Worker Settings add secret FREELLMAPI_UNIFIED_KEY (router unified key), FREELLMAPI_ACCESS_CLIENT_ID and FREELLMAPI_ACCESS_CLIENT_SECRET (Access service-token credentials). Existing HEALTH_AI_OWNER_TOKEN and HEALTH_AI_QUOTA are required. Set FREELLMAPI_ENABLED=true and FREELLMAPI_FREE_PROFILE_CONFIRMED=true only after reviewing the private profile and service-auth policy. Workers AI settings are independent. Preserve runtime variables across Git deploys. All five daily HealthOS reservations are shared between providers; failures count. This is a HealthOS request limit, not an upstream token/call budget. No automatic HealthOS retry or provider fallback.
## Verify
GET /api/health returns freeLLMAPI=true when local configuration is present, not a connectivity test. Open AI research providers, select FreeLLMAPI, enter owner token and consent, select a fixed topic. A successful result shows router-reported provider/model. No arbitrary prompts, clinical data, tools or uploads are accepted. No secrets in the browser except the existing transient HealthOS owner credential; router and Access keys remain Worker secrets. Mock tests only until operator activation. No live deployment, upstream execution or private network changes performed here.
