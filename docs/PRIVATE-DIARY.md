# Private facial diary pilot v0.15
Create a private R2 bucket healthos-storage (lowercase/hyphens); do not enable r2.dev or a public custom domain. Wrangler declares HEALTHOS_STORAGE. Keep DIARY_ENABLED=false until security/privacy review, real device testing, R2 integration test and appropriate access controls. Add unique high-entropy HEALTH_DIARY_OWNER_TOKEN secret (32–200 chars; distinct from AI token). This is a single-owner vault, not multi-user accounts. Prefer Cloudflare Access protecting the whole owner-only deployment before activating. Add rate limits for /api/diary. No R2 API key needed. After verifying deployment, set DIARY_ENABLED=true and check /api/health diary=true (configuration only). Do not put real medical records in this pilot.
Client AES-256-GCM with random 16-byte salt and 12-byte IV per save, PBKDF2 SHA-256 600000 iterations, passphrase never sent to Worker. Ciphertext only, 8 MiB maximum, fixed key private/facial-diary-v1.enc. Conditional ETags prevent stale overwrite. Browser stores decrypted data in memory while open; locks on view change/tab hide/pagehide. No password recovery. A compromised site/device/extension can access plaintext; encryption is not a substitute for trusted deployment. No clinical or regulatory compliance claim. 90 daily entries, optional resized JPEG, no automatic upload. User can remove entries and sync; to delete entire cloud object permanently use R2 dashboard after disabling diary (also delete encrypted backups if desired). R2 sees timestamps and object size. Export encrypted backup and restore with same passphrase. No AI inference or automatic causality. Comparison exact comma-delimited exposure vs other nonblank lists on rated days, minimum three each, descriptive only. Photos side by side, not automated skin scoring. Retention is user-managed; no automatic purge. Mock R2 tests do not establish live integration or security audit. No production configuration changed.
