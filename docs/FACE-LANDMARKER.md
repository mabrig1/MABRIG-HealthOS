# Experimental Face Landmarker v0.14
Implemented optional same-origin MediaPipe Tasks Vision runtime (CPU, VIDEO mode), two samples over eight seconds, reject multiple/no faces, report framing consistency and approximate regional lighting/detail only. Not a face health classifier, age estimator, identity system, pose certification, or cross-session skin progress measurement. Crops are approximations from geometry. No raw landmarks, crops or frames are persisted or exported by the application. Model is closed when camera stops or page is hidden. Standard no-model camera and habit features remain available.
## Reviewed assets required
The public build has no third-party model or WASM assets by default. Do not activate before reviewing runtime/model licenses, notices, package integrity and data behavior. Reference: https://developers.google.com/edge/api/mediapipe/js/tasks-vision and https://github.com/google-ai-edge/mediapipe . The upstream model is separate from the source license.
On a private test machine, obtain the exact @mediapipe/tasks-vision 0.10.21 package from npm and the versioned face_landmarker float16/1 task from Google's documented model distribution. Review third-party notices and permission to serve each file. Place these reviewed assets in untracked face-runtime-reviewed/: vision_bundle.mjs, face_landmarker.task, wasm/vision_wasm_internal.js, wasm/vision_wasm_internal.wasm, wasm/vision_wasm_nosimd_internal.js, wasm/vision_wasm_nosimd_internal.wasm. If a distribution does not have these exact names, do not substitute silently. Generate manifest.json with version "0.10.21", model "face-landmarker-float16-1", files object mapping the six relative paths to SHA256 hashes from the reviewed artifacts. Preserve required notices in your approved distribution. Set HEALTHOS_FACE_ASSETS_APPROVED=true for npm run build. The build checks each hash and copies only these files, removing previous runtime assets by default. The manifest verifies consistency against the operator-reviewed file set, not upstream authenticity by itself.
Start npm run start (localhost), start camera, then enable optional model and select landmark-guided check. Inspect network requests: no camera content or geometry should leave the device; validate runtime itself and browser behavior before serving to users. Test low light, multiple faces, missing assets, switching views, revoking consent and stopping mid-load. Runtime assets are not currently provisioned or executed by CI; software tests use synthetic landmark geometry. No production changes or clinical validation.
